# Проверка полного сценария поездки и отзывов — 03.6

## Подготовка

Запустите PostgreSQL и приложение по инструкции README. Используйте два отдельных профиля браузера: водитель и пассажир. Для проверки автоматического отклонения понадобится второй пассажир. Учебные аккаунты приведены в README. Реальные платежи не выполняются.

Выберите будущую дату и маршрут «Уралмаш → УрФУ, Мира, 19». Если в справочнике несколько подходящих точек, используйте их реальные названия. Создайте поездку на 3 места по 150 ₽. Откройте инструменты разработчика → Network → Fetch/XHR, включите сохранение запросов.

## Основной проход через интерфейс

1. Водитель: «Создать поездку», заполнить маршрут, время, автомобиль и условия. Сохранить черновик, открыть «Мои поездки», опубликовать с подтверждением. Ожидаются POST создания и публикации, статус «Опубликована».
2. Пассажир: найти поездку по району, дате, времени, цене и числу мест; открыть карточку. В Network видны GET поиска и деталей. Забронировать 2 места: POST бронирования возвращает PENDING, демо-платёж — PENDING; доступный остаток становится 1.
3. Второй пассажир: забронировать последнее место. Водитель видит обе заявки в списке пассажиров.
4. Водитель: подтвердить заявку первого пассажира. Она получает CONFIRMED, демо-платёж — SUCCEEDED. Пассажир видит поездку в предстоящих и уведомление о подтверждении.
5. Водитель: «Мои поездки» → «Начать поездку» → прочитать последствия → подтвердить. POST старта возвращает IN_PROGRESS и серверное startedAt. Начать можно вручную до запланированного отправления.
6. Первый пассажир и водитель получают уведомление о старте. Заявка второго пассажира отклоняется с причиной начала поездки, неоплаченный демо-платёж отменяется без списания; ему приходит уведомление об отклонении. Начатая поездка исчезает из публичного поиска и карточки.
7. Водитель: «Завершить поездку» → подтвердить. POST завершения возвращает COMPLETED и completedAt. Первый пассажир видит заявку в истории, а участники — уведомление о завершении. Успешный демо-платёж сохраняется без возврата.
8. Пассажир: «Мои заявки» → «История» → «Оценить водителя». Выбрать 5, написать осмысленный комментарий и отправить. В Network виден POST /api/bookings/<UUID>/reviews с rating/comment, ответ 201. В карточке появляется сохранённый отзыв.
9. Водитель: открыть «Уведомления», найти новый отзыв и перейти по ссылке в «Отзывы и рейтинги». В полученных отзывах видны оценка пассажира и рейтинг «Как водитель».
10. Водитель: «Заявки пассажиров» → «История» → «Оценить пассажира», отправить оценку 4 и комментарий. У каждого пассажира отдельная заявка и отдельный отзыв.
11. Пассажир: открыть уведомление о встречном отзыве, перейти в полученные отзывы. Рейтинг «Как пассажир» обновлён; в «Оставленных» сохраняется собственная оценка водителя. Фильтры списка не изменяют итоговый рейтинг.
12. Открыть другую будущую опубликованную поездку того же водителя: карточка показывает его актуальный рейтинг и число отзывов. Оценки как пассажира не смешиваются с рейтингом водителя. Сама завершённая поездка остаётся недоступной в публичной карточке.
13. Обновить страницу и снова войти в аккаунт: история, отзывы и рейтинги сохраняются в PostgreSQL. Повторная форма уже оставленного отзыва не предлагается. Открыть уведомление и убедиться, что отметка прочтения сохраняется.

## Ошибки и повторы

- До подтверждения начала или завершения POST не отправляется. Во время запроса кнопки заблокированы.
- При сетевой ошибке подтверждение остаётся открытым для безопасного повтора. Повтор успешного старта/завершения возвращает прежнее время и не создаёт новых событий или уведомлений.
- Устаревший статус даёт 409 и обновление списка. Чужая поездка — 404; без сессии — 401; без роли водителя — 403.
- Отзыв доступен только участнику завершённой заявки завершённой поездки. Повторная оценка даёт 409, чужая заявка — 404; отклонённая заявка не даёт права на отзыв. Ожидаются ровно два встречных отзыва, два уведомления и две записи review.created. При сетевой ошибке форма сохраняет ввод; после потерянного ответа повтор может вернуть 409 и загрузить уже принятый отзыв.
- После начала обычная отмена недоступна; после завершения повторный старт запрещён. Реальные списания и возвраты отсутствуют.
- Проверьте ширину 390 px и десктоп: фильтры, карточки, подтверждение, длинные условия и причины должны оставаться читаемыми без горизонтальной прокрутки. Это ручной контроль отображения, а не результат автоматического HTTP-теста.

## Автоматическая проверка

`bun run check` запускает форматирование, линтер, проверку типов, тесты и сборку. В `apps/api/test/bookings.e2e-spec.ts` единый сценарий проходит через настоящее HTTP-приложение и PostgreSQL: создание черновика → публикация → поиск с фильтрами → карточка → две заявки → подтверждение → предстоящие → старт с автоотклонением → завершение → история → встречные отзывы → рейтинги → уведомления → безопасные повторы. Проверяются точная сумма демо-платежа, сохранение оплаты, события статусов, получатели уведомлений, раздельные рейтинги, рейтинг в другой публичной карточке водителя и запреты отмены, повторной и чужой оценки. Тестовые записи удаляются после выполнения.

Сценарий ReviewFlow.test.tsx проходит интерфейс App со сменой аккаунтов: история → отзыв водителю → оставленные отзывы → уведомление водителя → оценка пассажира → уведомление пассажира → полученные отзывы и рейтинги → повторное открытие истории. Этот тест использует подмену HTTP и дополняет HTTP-тест с настоящей PostgreSQL. Компонентные тесты отдельно проверяют ошибки, загрузку, двойную отправку и скрытые отзывы. Единый HTTP-тест не заменяет ручную проверку вёрстки в браузере.

## Текущая граница готовности

Полный проход до завершённой поездки, встречных отзывов и раздельных рейтингов реализован. Управление пользователями, модерация и собственная история администратора проверяются в [административном сценарии](demo-admin.md). Главные экраны кабинетов и статистика водителя реализованы. Остаётся итоговая проверка полноты фильтров, адаптивности, демо-данных и воспроизводимого запуска.

На главной водителя после завершения поездки обновите статистику: выбранный период относится к отправлению. Число уникальных аккаунтов пассажиров может отличаться от числа мест. После отмены/возврата демо-поступления исключают возвращённый платёж, возврат показан отдельно. На главной пассажира отображается ближайшая будущая заявка и общее число предстоящих заявок.
