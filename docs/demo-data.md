# Демо-данные справочников маршрутов

Подготовка: запустить PostgreSQL, применить миграции (`bun run db:deploy`), выполнить `bun run db:seed` из корня проекта. Команда готовит демо-аккаунты и справочники маршрутов. Seed не запускается автоматически при старте приложения.

## Состав

- Пять жилых районов и микрорайонов: Втузгородок, Центр, Академический, Уралмаш, Ботанический. Это пользовательские зоны поиска, а не исключительно административное деление города.
- Три корпуса УрФУ: главный учебный корпус на Мира, 19; корпуса на Тургенева, 4 и Куйбышева, 48.
- Семь точек: три корпуса (`CAMPUS`), ориентир у главного корпуса и перекрёсток в Академическом (`MEETING_POINT`), станции метро «Уралмаш» и «Ботаническая» (`TRANSIT_STOP`).

Точки встречи — демонстрационные ориентиры, а не зарезервированные места посадки или парковки. Конкретное место встречи водитель уточнит в условиях поездки. Координаты и интеграция с картой в этот этап не входят.

## Повторяемость

Источник — `apps/api/src/demo/seed-routes.ts`. Исходные записи имеют постоянные UUID. Повторный запуск сохраняет существующие строки: названия, адреса, типы и связи не перезаписываются. Для района или корпуса сначала проверяется исходный UUID; если его нет, одноимённая существующая запись используется повторно, а ссылки новых точек направляются на её фактический UUID.

Справочники создаются в одной транзакции. Ошибка ссылки откатывает весь набор справочников. Аккаунты подготавливаются отдельной транзакцией и не удаляются при ошибке справочников. Seed не удаляет пользовательские данные и не сбрасывает внесённые изменения. Точки сопоставляются по постоянным UUID, а не по неуникальному названию.

HTTP-тесты используют собственные UUID и имена с уникальным префиксом, после завершения удаляют только свои записи. Проверяются поиск, фильтры, пагинация, повтор seed, сохранение изменений, повторное использование одноимённых справочников и откат при ошибке.
