# Проверка административных сценариев — 04.6

## Подготовка

Запустите приложение и PostgreSQL по README. Откройте независимые профили браузера для администратора, водителя и пассажира. Используйте учебные аккаунты из README; для блокировки выберите отдельного пассажира. Администратор не может менять собственную блокировку.

Для первого сценария нужна будущая опубликованная поездка, например «Уралмаш → УрФУ, Мира, 19», 3 места по 150 ₽. Пассажир бронирует 2 места, водитель подтверждает заявку. До блокировки заявка имеет CONFIRMED, демо-платёж — SUCCEEDED на 300 ₽. Для модерации подготовьте завершённую поездку с встречными отзывами по [основному сценарию](demo-lifecycle.md).

В инструментах разработчика включите Network → Fetch/XHR и сохранение запросов. Реальные деньги не используются. Проверку отображения выполните на десктопе и ширине 390 px: фильтры, подтверждения, длинные причины и карточки должны оставаться читаемыми без горизонтальной прокрутки.

## Блокировка → прекращение доступа → возврат → разблокировка

1. Администратор: «Пользователи». Найти пассажира по имени/email, при необходимости применить роль, статус, принадлежность и даты регистрации. В Network виден GET /api/admin/users с фильтрами.
2. Нажать «Заблокировать». Проверить имя/email и последствия. До подтверждения POST не отправляется. Указать причину и подтвердить: POST /api/admin/users/<UUID>/block возвращает BLOCKED, changed=true и счётчики отмен/сессий.
3. Пассажир: обновить «Мои заявки». API возвращает 401, приложение предлагает вход; войти заблокированным аккаунтом нельзя. Другие открытые сессии этого аккаунта также прекращают доступ.
4. Водитель: обновить «Заявки пассажиров». Заявка отменена по административной причине, демо-платёж полностью возвращён. Другая заявка другого пассажира остаётся активной. Водитель видит уведомление об отмене, пассажиру сохранено уведомление о возврате.
5. Администратор: «Мои действия». Найти блокировку и связанные отмену заявки/возврат. Видны причина и время; чужие действия не показываются. Повтор блокировки через Swagger возвращает changed=false и не делает второй возврат.
6. В списке пользователей нажать «Разблокировать», указать причину и подтвердить. Пользователь становится ACTIVE. Старая сессия остаётся недействительной: пассажир входит заново.
7. Пассажир: открыть историю. Отменённая заявка и возврат сохранились; активное участие автоматически не восстановилось. В уведомлениях доступны решения о блокировке/разблокировке и возврат. Администратор видит отдельную запись разблокировки в своей истории.

Если блокируется пользователь с ролью водителя, его будущие не начатые DRAFT/PUBLISHED-поездки отменяются вместе с активными заявками всех пассажиров. При двух ролях дополнительно отменяются его заявки в других будущих поездках. Начатые, завершённые и прошедшие поездки сохраняются.

## Скрытие → изменение рейтинга → восстановление

1. Зафиксировать исходный рейтинг водителя в «Отзывах и рейтингах» и карточке другой будущей поездки этого водителя. Завершённая поездка в публичном поиске недоступна.
2. Администратор: «Модерация отзывов». Найти отзыв по тексту/имени, видимости, роли получателя, оценке и датам. Проверить участников, оценку и статус участия.
3. Нажать «Скрыть», прочитать последствия, ввести причину и подтвердить. POST /api/admin/reviews/<UUID>/hide возвращает hiddenAt и changed=true. С фильтром «Видимые» отзыв исчезает, с фильтром «Скрытые» отображается с причиной.
4. Автор и получатель: обновить собственные отзывы и рейтинги. Отзыв скрыт; рейтинг и число оценок уменьшаются. Если других оценок нет, среднее равно null, интерфейс показывает «Пока нет оценок». После обновления публичной карточки водителя результат совпадает. Новая оценка по той же заявке запрещена.
5. Администратор: открыть уведомление о модерации и перейти в связанный раздел. В «Моих действиях» есть скрытие с причиной и номером отзыва. Участникам сохранены отдельные уведомления о решении.
6. Найти скрытый отзыв и нажать «Восстановить». Указать причину восстановления и подтвердить: POST /api/admin/reviews/<UUID>/restore возвращает hiddenAt=null, hiddenReason=null. Первоначальные оценка и комментарий сохраняются.
7. Обновить списки, рейтинги и публичную карточку: подходящий отзыв снова учитывается. В истории остаются оба решения с разными причинами. Повтор восстановления возвращает changed=false без дублей уведомлений и журнала.

## Проверки прав и ошибок

- Пассажир и водитель не видят административные ссылки; прямой административный запрос возвращает 403. Без сессии — 401. Утрата роли ADMIN на сервере закрывает доступ независимо от открытого интерфейса.
- Собственный аккаунт не имеет кнопки блокировки; команда по API возвращает 409. Пустая причина, лишнее поле или неверный UUID дают 400, отсутствующий объект — 404.
- При сетевой ошибке подтверждение сохраняет причину для повтора. После успешной команды с ошибкой перечитывания списка повторяется только GET. Во время POST остальные действия заблокированы.
- Некорректный демо-платёж или сбой записи отменяет всю блокировку, включая изменения сессий. Сбой уведомления/журнала откатывает модерацию и её влияние на рейтинг. Эти отказы проверяются автоматически; специально повреждать данные для демонстрации не требуется.

## Автоматическая проверка и документация API

`bun run check` проверяет форматирование, линтер, типы, тесты и сборку. HTTP-сценарий в user-status.e2e-spec.ts использует настоящее приложение и PostgreSQL: бронирование → подтверждение → поиск пользователя → блокировка → отказ в доступе → возврат → разблокировка → новый вход → история и уведомления. В bookings.e2e-spec.ts сценарий модерации проверяет скрытие, обе роли рейтинга, публичную карточку, восстановление, историю и уведомления.

AdminFlow.test.tsx проходит формы блокировки/разблокировки и скрытия/восстановления через App, уведомление и историю с подменой HTTP. Он проверяет связность интерфейса и дополняет HTTP-тесты с БД. Проверки вёрстки и Network выше — отдельный ручной проход, а не результат этих тестов.

Swagger доступен по /api/docs, JSON — /api/docs-json. Проверены административные маршруты, cookie-сессия и обязательная причина обеих команд блокировки и модерации. Общее описание Swagger отражает текущее реализованное API.
