# Отмены и пограничные случаи — 06.4

Проверка 6 ноября 2026 года выполнена HTTP-тестами настоящего NestJS-приложения с PostgreSQL. Тесты создают собственные аккаунты, поездки, заявки и платежи; после выполнения удаляют свои данные. Реальные деньги не используются. Браузерный проход в этот этап не входит.

## Матрица проверок

| Сценарий                                            | Ожидаемый и проверяемый результат                                                                                        |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Водитель отклоняет PENDING                          | REJECTED, сохранена причина, места освобождены, ожидающий платёж CANCELLED без возврата, пассажир уведомлён              |
| Пассажир отменяет PENDING                           | CANCELLED, резерв освобождён, списания нет                                                                               |
| Пассажир отменяет CONFIRMED                         | CANCELLED, платёж REFUNDED на полную исходную сумму, места доступны                                                      |
| Водитель отменяет поездку                           | Все активные заявки отменены: подтверждённые платежи возвращены, ожидающие отменены; поездка скрыта из поиска и карточки |
| Повтор или параллельные отмены                      | Один возврат, одно событие перехода и отсутствие повторных уведомлений; исходная причина не перезаписывается             |
| Повтор бронирования с тем же requestKey             | Та же заявка, без нового резерва; изменение параметров ключа запрещено                                                   |
| Два пассажира претендуют на остаток                 | Резерв не превышает вместимость, один конфликт 409                                                                       |
| Подтверждение одновременно с отменой                | Не остаётся успешной невозвращённой оплаты у отменённой заявки                                                           |
| Освобождение одновременно с новой заявкой           | Перепродажи нет; после конфликта новый запрос может повториться                                                          |
| Начатая поездка и прошедшее отправление             | Недопустимые обычные отмены отклоняются                                                                                  |
| Чужой аккаунт, неподходящая роль, сессия или Origin | Команда не меняет данные                                                                                                 |
| Ошибка уведомления или возврата внутри транзакции   | Изменения заявки, поездки, платежа и истории откатываются вместе                                                         |

## Новая сквозная регрессия

В `apps/api/test/bookings.e2e-spec.ts` добавлен тест «последнее место»: вместимость 1, два конкурентных POST от разных пассажиров → ответы 201 и 409. Победитель подтверждён; повтор проигравшего по-прежнему получает 409. Две параллельные отмены победителя возвращают оплату один раз. Проигравший повторяет исходный requestKey и получает новую заявку 201; следующий повтор возвращает ту же заявку 200. В БД остаются одна активная заявка, один возвращённый платёж и одна запись payment.refunded.

Это дополняет существующие отдельные проверки гонок, отмен и отклонений: проверяется последовательность освобождения и повторного использования последнего места, а не только каждый переход изолированно.

## Повторение

```sh
bun run check
```

Команда включает проверку Prisma, форматирование, линтеры, типы, HTTP- и интерфейсные тесты, сборку. Интерфейсные тесты Bookings, DriverBookings, BookingForm и Rides проверяют формы отмены/отклонения, подтверждение команды, ошибки и повтор загрузки. Инструкция для ручного показа отмен и возвратов находится в [жизненном цикле](demo-lifecycle.md).
