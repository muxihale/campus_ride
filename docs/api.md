# Контракт API

Базовый префикс: `/api`. Формат данных — JSON. Время — ISO 8601 с часовым поясом, идентификаторы — UUID, деньги — целые копейки. Данные об авторе и суммах сервер берёт из сессии и БД.

## Что реализовано сейчас

- `GET /health` — `{ "status": "ok", "service": "campusride-api" }`, без обращения к БД.
- `GET /health/ready` — дополнительно `"database": "connected"` при успешном `SELECT 1`; иначе `503`.
- `GET /docs` — Swagger UI.
- `GET /docs-json` — машиночитаемый OpenAPI.
- `POST /auth/register` — `{ email, password, fullName, affiliation? }`; создаёт пассажира и сессию, возвращает `201` и `{ id, email, fullName, affiliation, roles }`. Email приводится к нижнему регистру, пробелы по краям email/имени удаляются; пароль не обрезается. Роль всегда `PASSENGER`, неизвестные поля запрещены.
- `POST /auth/login` — `{ email, password }`; создаёт новую семидневную сессию, возвращает `200` и безопасные данные пользователя. Неверные учётные данные и заблокированный аккаунт дают одинаковый `401`, неверные/лишние поля — `400`. Лимит — 10 попыток с IP за 60 секунд, независимо от регистрации, включая невалидные формы.
- `POST /auth/logout` — удаляет только текущую сессию и очищает cookie, `204`; повторный выход, отсутствующая или истёкшая сессия также успешны.
- `GET /auth/me` — те же безопасные данные по cookie `campusride_session`, `200`; при отсутствующей, неверной, истёкшей или удалённой сессии и блокировке пользователя — `401`.

- `GET /me` — собственный профиль `{ id, email, fullName, phone, affiliation, roles }` по действующей сессии, `200`. Ответ не содержит паролей, хешей и данных сессии.
- `PATCH /me` — частичное изменение `{ fullName?, phone?, affiliation? }`, возвращает обновлённый профиль, `200`. Требует разрешённый `Origin`. Пропущенные поля сохраняются; имя обрезается по краям и должно содержать 2–100 символов, `null` для имени запрещён. Телефон — до 32 символов, цифры, пробелы, скобки, дефисы и необязательный `+` в начале; принадлежность — до 200 символов. Для телефона и принадлежности `null` и пустая строка после обрезки очищают значение. Неизвестные поля, включая `id`, `userId`, `email`, `password`, `status` и `roles`, запрещены (`400`); неверный Origin — `403`; нет активной сессии — `401`; недоступность БД — `503`. Выбрать чужого пользователя через этот маршрут нельзя: идентификатор берётся только из серверной сессии.

- `POST /me/driver-profile` — `{ bio?, vehicle: { make, model, color, registrationNumber, passengerSeats } }`; требует действующую сессию с ролью `PASSENGER` и разрешённый Origin. В одной транзакции создаёт профиль водителя, первый автомобиль и роль `DRIVER`, сохраняя остальные роли и сессии. Возвращает `201` и обновлённый профиль пользователя в формате `GET /me`. Повторное подключение или занятый госномер — `409`, без частичного сохранения. Неверные/лишние поля (включая вложенные) — `400`, нет роли пассажира или чужой Origin — `403`, нет активной сессии — `401`, сбой БД — `503`.

Описание водителя необязательно, до 1000 символов. Марка и модель — 1–60, цвет — 1–40 символов после обрезки пробелов. Пассажирских мест — целое число 1–8, без водителя. Поддерживается стандартный госномер легкового автомобиля РФ вида `А123ВС196`: пробелы удаляются, буквы приводятся к верхнему регистру и латинским соответствиям (`A123BC196`). Это обеспечивает единую уникальность для кириллицы и латиницы. `userId`, `driverId`, `id`, роли и другие служебные поля не принимаются.

- `GET /me/vehicles` — только свои автомобили с поиском, фильтрами и пагинацией; требуется роль `DRIVER`. Параметры: `q` (до 100 символов, поиск по марке, модели, цвету и нормализованному госномеру), `make`, `model`, `color` (по подстроке без учёта регистра), `minSeats` и `maxSeats` (1–8). Поиск и фильтры объединяются через «И». `page` — 1–1 000 000, по умолчанию 1; `pageSize` — 1–100, по умолчанию 20. Ответ `{ items, total, page, pageSize }`; сортировка по времени создания от новых к старым, затем по UUID для стабильной пагинации.
- `POST /me/vehicles` — добавляет автомобиль `{ make, model, color, registrationNumber, passengerSeats }` текущему водителю, возвращает `201` и автомобиль. Если у подготовленного аккаунта `DRIVER` нет профиля водителя, пустой профиль создаётся в той же транзакции; роли и существующее описание не меняются.
- `PATCH /me/vehicles/:id` — частично меняет перечисленные поля своего автомобиля, возвращает `200` и автомобиль. Пропущенные поля сохраняются; `null` запрещён. Чужой и отсутствующий UUID одинаково возвращают `404`.

Объект автомобиля содержит только `id`, `make`, `model`, `color`, `registrationNumber`, `passengerSeats`, `createdAt`. Мутации автомобилей требуют разрешённый Origin; все маршруты требуют активную сессию и роль `DRIVER`. Валидация и нормализация совпадают с первым автомобилем при подключении водителя: марка/модель 1–60, цвет 1–40, стандартный госномер легкового автомобиля РФ, 1–8 пассажирских мест. Занятый нормализованный номер даёт `409` без частичного сохранения. Лишние поля и параметры, неверный UUID или диапазон мест — `400`, нет сессии — `401`, нет роли/чужой Origin — `403`, сбой БД — `503`. `driverId` нельзя передать для изменения владельца или выбора чужого списка.

- `GET /districts` — публичный список районов/микрорайонов: поиск `q` по названию; фильтры `kind`, `address`, `locationName`, `campusId` по связанной точке.
- `GET /campuses` — публичный список корпусов УрФУ: поиск `q` по названию; фильтры `kind`, `address`, `locationName`, `districtId` по связанной точке.
- `GET /locations` — публичный список точек маршрутов: поиск `q` по названию или адресу; четыре фильтра `districtId`, `campusId`, `kind`, `address`.

Справочники возвращают `{ items, total, page, pageSize }`. Район и корпус содержат `{ id, name }`; точка — `{ id, name, address, kind, districtId, campusId, district: { id, name }, campus: { id, name } | null }`. `campusId` может быть `null` для точек вне кампуса. Списки без фильтров включают районы и корпуса без точек. Связанные фильтры применяются к одной точке, а не к разным точкам одного корпуса/района.

Поиск и текстовые фильтры — подстрока без учёта регистра, условия объединяются через «И». `kind` — `CAMPUS`, `MEETING_POINT` или `TRANSIT_STOP`; идентификаторы — UUID. `q` и `locationName` — до 100 символов, `address` — до 200; `page` — 1–1 000 000 (по умолчанию 1), `pageSize` — 1–100 (по умолчанию 20). Сортировка по названию, затем UUID. Неверные и лишние параметры дают `400`, неизвестный корректный UUID — пустой список `200`, недоступная БД — безопасный `503`. Сессия для чтения справочников не требуется; публичных маршрутов изменения нет.

- `POST /rides` — создание полностью заполненного черновика, `201`. Требует активную сессию с ролью `DRIVER` и разрешённый `Origin`. Тело: `{ vehicleId, originId, destinationId, departureAt, seatsTotal, priceKopecks, conditions, musicAllowed?, luggageAllowed?, smokingAllowed?, stops? }`. Музыка по умолчанию разрешена, багаж и курение — нет; остановки по умолчанию `[]`. `conditions` — обязательный текст условий и уточнения места встречи, 1–1000 символов после обрезки пробелов.

Создание проверяет принадлежность автомобиля водителю (чужой и отсутствующий — одинаковый `404`), наличие всех точек и отсутствие повторов в маршруте, включая остановки и конечные точки. `seatsTotal` — целое 1–8 и не больше вместимости автомобиля. Цена за место — целые копейки 0–2 147 483 647, включая бесплатные поездки. Время — строгая ISO 8601 дата с `T` и явным часовым поясом (`Z` или `+05:00`), обязательно в будущем; ответ нормализован в UTC.

Допускается до 10 промежуточных остановок `{ locationId }` в порядке посещения; позиции 1, 2, … назначает сервер. Черновик и остановки создаются в одной транзакции. Автор берётся только из сессии, статус всегда `DRAFT`; `driverId`, `status`, `id`, `availableSeats`, клиентские позиции остановок и другие лишние поля запрещены. Ошибки валидации и бизнес-условий — `400`, нет сессии/блокировка — `401`, нет роли/неразрешённый Origin — `403`, недоступность БД — безопасный `503`.

Ответ создания содержит `id`, `driverId`, поля запроса с настройками по умолчанию, `status`, `createdAt`, `updatedAt` и `stops: [{ id, locationId, position }]`. Он не содержит аккаунт, пароли, сессии или бронирования. Создание не публикует поездку; повторный корректный POST создаёт отдельный черновик. При будущей публикации время и вместимость будут проверены повторно.

Регистрация требует `Origin`, точно совпадающий с `WEB_ORIGIN` (`403` при несовпадении/отсутствии), принимает максимум 10 попыток с одного IP за 60 секунд (`429`, заголовок `Retry-After`). Валидация полей возвращает `400`, повторный email — `409`. Создание аккаунта, роли и сессии атомарно; при параллельных запросах одинакового нормализованного email создаётся только один аккаунт.

Токен — 32 случайных байта; в БД хранится SHA-256-хеш, в cookie — исходный токен. Пароль хешируется Argon2id. Cookie: `HttpOnly`, `SameSite=Lax`, `Path=/`, срок 7 дней, `Secure` при `NODE_ENV=production`. Токен, его хеш и пароль/хеш пароля не возвращаются в JSON. Успешные ответы маршрутов авторизации и профиля имеют `Cache-Control: no-store`.

Для работы с регистрацией из Swagger открывайте <http://localhost:5173/api/docs>, чтобы браузер отправлял разрешённый Origin. CLI-клиент указывает `Origin` явно и сохраняет cookie. Вход и выход также требуют точного совпадения Origin с WEB_ORIGIN.

Маршруты ниже — целевой контракт. Они ещё не реализованы и не должны появляться в Swagger как работающие до реализации.

## Правила целевых маршрутов

Списки принимают `q`, `page` (от 1), `pageSize` (по умолчанию 20, максимум 100) и разрешённую сортировку `sort`. Ответ: `{ items, total, page, pageSize }`. Фильтры определены в [спецификации](specification.md#10-поиск-и-фильтры). Параметры разных фильтров объединяются через «И».

Ошибки используют стандартный безопасный ответ NestJS: `{ statusCode, message, error }`; `message` может быть массивом ошибок полей. Для конфликтов бронирования прикладной ответ дополнительно содержит стабильный `code`, например `INSUFFICIENT_SEATS`, и `availableSeats`, если это уместно. Stack trace и данные подключения не возвращаются.

- `400`: неверные поля или параметры.
- `401`: нет действующей сессии.
- `403`: роль или состояние пользователя не разрешает действие.
- `404`: объект не существует или закрыт от текущего пользователя.
- `409`: недостаточно мест, повторное активное бронирование, изменённый идемпотентный запрос или недопустимый переход.
- `429`: превышена частота запросов.

Мутации не принимают произвольный статус через общий `PATCH`: для переходов используются отдельные команды. Повтор успешно выполненной статусной команды возвращает текущее представление без повторных побочных действий.

## Вход, профиль и настройки

- `PUT /me/password` — `{ currentPassword, newPassword }`; меняет пароль, отзывает остальные сессии, `204`.
- `GET /me/activity` — собственная история с поиском и фильтрами.

Минимальная длина пароля — 10, максимальная — 128 символов; имя — 2–100, телефон — до 32, принадлежность — до 200, описание условий — до 1000. Пустые строки нормализуются; пароли не обрезаются и не возвращаются в ответах.

## Поездки

- `GET /rides` — публичный поиск.
- `GET /rides/:id` — карточка с вычисленным остатком, публичными данными водителя и рейтингом.
- `GET /me/rides` — собственные поездки водителя с поиском и фильтрами.
- `PATCH /rides/:id` — изменение разрешённых полей своей поездки.
- `DELETE /rides/:id` — удаление собственного черновика без бронирований, `204`.
- `POST /rides/:id/publish` — публикация полностью заполненного черновика.
- `POST /rides/:id/start` — ручное начало своей поездки; отклоняет ожидающие заявки.
- `POST /rides/:id/complete` — завершение; обновляет подтверждённые бронирования и уведомляет участников.
- `POST /rides/:id/cancel` — `{ reason }`; отмена с обработкой бронирований и демо-платежей.
- `GET /rides/:id/bookings` — поиск и фильтрация пассажиров/заявок, только водитель этой поездки или администратор.
- `GET /me/driver-statistics` — завершённые поездки, перевезённые места, демо-выручка, рейтинг; параметры периода.

Пример уже реализованного `POST /rides` (остальные маршруты раздела пока целевые):

```json
{
  "vehicleId": "<UUID автомобиля>",
  "originId": "<UUID места встречи>",
  "destinationId": "<UUID корпуса>",
  "departureAt": "2026-11-09T08:00:00+05:00",
  "seatsTotal": 3,
  "priceKopecks": 15000,
  "musicAllowed": true,
  "luggageAllowed": true,
  "smokingAllowed": false,
  "conditions": "Встречаемся у входа со стороны парковки. Есть место для рюкзака.",
  "stops": []
}
```

Вместо текстовых заглушек передаются существующие UUID. Каждый элемент `stops` содержит `locationId`; порядок элементов определяет порядок остановок. Создание не принимает `driverId` или `status` от клиента.

Поиск поддерживает `direction=TO_CAMPUS|FROM_CAMPUS`, `originDistrictId`, `campusId`, `date=YYYY-MM-DD`, `timeFrom=HH:mm`, `timeTo=HH:mm`, `maxPriceKopecks`, `minSeats`, `luggageAllowed`, `musicAllowed`. Дата и часы относятся к Екатеринбургу. Для собственных поездок дополнительно доступен `status`. Публичный поиск всегда ограничен `PUBLISHED`, будущим отправлением и положительным остатком.

## Бронирование и демонстрационный платёж

- `POST /rides/:id/bookings` — `{ seats, requestKey }`; заявка с резервированием мест, `201`, повтор того же запроса — `200` с прежней заявкой.
- `GET /me/bookings` — собственные заявки и история с фильтрами.
- `GET /bookings/:id` — детали; только участник, водитель соответствующей поездки или администратор.
- `POST /bookings/:id/confirm` — только водитель; подтверждает и имитирует успешную оплату.
- `POST /bookings/:id/reject` — `{ reason }`, только водитель; освобождает места.
- `POST /bookings/:id/cancel` — `{ reason? }`, только пассажир-владелец до отправления; при необходимости выполняет полный демо-возврат.

Объект бронирования содержит статус, число мест, зафиксированную цену за место, сумму, платёж и краткую поездку. Отдельного публичного маршрута, позволяющего клиенту выставить `SUCCEEDED`/`REFUNDED`, нет.

## Отзывы и уведомления

- `POST /bookings/:id/reviews` — `{ rating, comment }`; сервер определяет получателя по участникам, `201`.
- `GET /me/reviews` — свои отправленные и полученные отзывы.
- `GET /users/:id/reviews` — только нескрытые отзывы и публичные данные с фильтрами.
- `GET /notifications` — только свои уведомления: `q`, `kind`, `read`, `dateFrom`, `dateTo`, `resourceType`.
- `PATCH /notifications/:id/read` — помечает своё уведомление прочитанным.
- `POST /notifications/read-all` — помечает все текущие уведомления пользователя прочитанными, `204`.

## Административные маршруты

- `GET /admin/users`, `GET /admin/rides`, `GET /admin/bookings`, `GET /admin/reviews`, `GET /admin/activity` — поиск, фильтры и пагинация.
- `POST /admin/users/:id/block` — `{ reason }`; отзывает сессии и отменяет будущие активные участия.
- `POST /admin/users/:id/unblock` — разблокировка с записью в аудит.
- `POST /admin/rides/:id/cancel` — `{ reason }`; использует тот же прикладной сценарий отмены и возвратов.
- `POST /admin/reviews/:id/hide` — `{ reason }`; скрытие и обновление рейтинга.
- `POST /admin/reviews/:id/restore` — восстановление и обновление рейтинга.

Каждая административная мутация проверяет роль на сервере, записывает автора и причину в аудит, создаёт уведомление затронутому пользователю и подтверждение результата в кабинете администратора.
