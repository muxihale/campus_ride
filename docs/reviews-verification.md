# Итоговая проверка завершения и отзывов — 06.3

6 ноября 2026 года проверен работающий интерфейс Vite → NestJS → PostgreSQL. Продолжена поездка из проверки [06.2](demo-booking.md): два подтверждённых места по 150 ₽. Использованы демо-аккаунты водителя, пассажира и администратора, независимые профили Default/Incognito.

## Фактический проход

1. Водитель открыл «Мои поездки», выбрал поездку по пометке 06.2 и подтвердил начало. Статус стал «В пути», появилось серверное время начала.
2. Водитель нажал «Завершить поездку» и подтвердил действие. Поездка и заявка стали завершёнными. В заявке сохранён оплаченный демо-платёж 300 ₽; возврата нет.
3. В «Заявках пассажиров» водитель открыл форму оценки пассажира и отправил 4 с комментарием о своевременном прибытии. GET /api/users/:id/ratings вернул passenger.average=4, count=1; водительский рейтинг этого пользователя остался пустым.
4. В независимом профиле пассажир открыл «Мои заявки», форму оценки водителя и отправил 5 с комментарием о поездке. Рейтинг водителя стал driver.average=5, count=1; пассажирский рейтинг водителя остался пустым.
5. Администратор открыл «Модерация отзывов». Видны оба встречных отзыва одной завершённой заявки: 5 водителю и 4 пассажиру.
6. Администратор скрыл отзыв водителю с учебной причиной через форму подтверждения. После выполнения запроса рейтинг водителя стал average=null, count=0: скрытая оценка исключена из расчёта.
7. Администратор восстановил отзыв с причиной завершения проверки. Повторно проверен возврат рейтинга. Отзыв оставлен видимым.

Причины модерации относятся к учебной проверке, а не к нарушению со стороны участников. Бизнес-логика не менялась: дефектов этого прохода не обнаружено. Состояние после подтверждения команды следует проверять после окончания POST и обновления GET, а не сразу после нажатия кнопки.

## Повторяемая автоматическая проверка

Успешно выполнены:

```sh
bun run --filter @campusride/api test test/bookings.e2e-spec.ts -t 'полный сценарий: черновик|полный административный сценарий'
bun run --filter @campusride/web test src/ReviewFlow.test.tsx src/AdminFlow.test.tsx
```

Два HTTP-теста с PostgreSQL проверяют завершение, встречные отзывы, рейтинги, уведомления, скрытие/восстановление, административную историю и публичную карточку. Два интерфейсных теста проходят формы и переходы с подменой HTTP. Браузерный проход выше дополняет их реальным соединением фронтенда и API. Правила безопасного повторения и ожидаемые сетевые запросы описаны в [жизненном цикле](demo-lifecycle.md) и [административных сценариях](demo-admin.md).
