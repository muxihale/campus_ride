# Защита CampusRide — 06.6

Защита: 9 ноября 2026 года. Цель показа — работающий путь пассажира и водителя с настоящими запросами, затем отзывы, возврат и административная модерация. Реальных платежей нет.

## Перед показом

1. Запустите сервис по README, примените миграции и `bun run db:seed`.
2. Подготовьте будущие поездки, пока фронтенд и API работают:

```sh
DEMO_DATE=2026-11-09 bun scripts/prepare-defense.mjs
```

В Docker скрипт можно выполнить на хосте с Bun: он обращается к http://localhost:5173. Для другого адреса задайте DEMO_BASE_URL. Без DEMO_DATE выбирается дата через три дня от запуска. Дата должна быть в будущем относительно отправления 08:30 Екатеринбурга.

Скрипт входит демо-водителем, выбирает seed-точки Уралмаш и главный корпус Мира, 19, использует автомобиль на три места либо создаёт Kia Rio. Публикует две поездки на 3 места по 150 ₽: «Основная поездка» в 08:30 и «Отмена и возврат» в 09:00. Выводит прямые ссылки. Повтор использует существующие DRAFT/PUBLISHED с той же пометкой и датой. После завершения/отмены создаёт замену. Резервы существующей опубликованной поездки не сбрасываются: для полностью новой репетиции выберите другую будущую дату. Пользовательские данные не удаляются.

3. Откройте независимые профили: пассажир passenger@campusride.test, водитель driver@campusride.test, администратор admin@campusride.test. Пароль всех демо-аккаунтов — CampusRide-demo-2026. Администратора можно показать после выхода водителя. Две вкладки одного профиля разделяют сессию.
4. Включите DevTools → Network → Fetch/XHR → Preserve log. Проверьте /api/health/ready. Откройте заранее Swagger /api/docs и [диаграмму](database.md). Не экспортируйте cookie в публичные материалы.

Старт и завершение разрешены вручную до даты отправления для демонстрации. После старта ожидающие заявки отклоняются, поэтому подтверждайте основную заявку заранее. После завершения публичная карточка закрывается; история и отзыв доступны из кабинета. Перед каждой новой репетицией проверьте состояния поездок, а не только их наличие.

## Что объяснить при вопросах

- PENDING резервирует места сразу; подтверждение не резервирует их второй раз.
- Транзакции и блокировка поездки защищают последнее место. requestKey защищает повтор отправки; возврат идемпотентен.
- Цена фиксируется сервером в заявке. Оплата/возврат — имитация, сумма в копейках.
- Отзыв возможен только между участниками завершённой заявки. Скрытый отзыв исключается из рейтинга.
- Карта, GPS, чат, внешние рассылки и реальные платежи не входят в первую версию. Другие фактические ограничения перечислены в [сверке](requirements-audit.md).
